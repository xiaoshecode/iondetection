# 把图像放在哪里

所有路径相对于项目根目录。请放原始灰度图，不要放带圈截图、伪彩色图或自动拉伸后的预览图。

2026-11-03 已导入已有原始数据：`train` 426 张、`val` 250 张、`test` 263 张，另有 `diagnostic` 5 张。每张图的原路径、目标路径、文件和像素 SHA256、尺寸及划分记录在本地 `existing_import_manifest.json`。原始文件未修改；采集 JSON/JSONL 同时保存。`session_001` 等 `.gitkeep` 空目录是给后续采集保留的，不参与读取。

现有 PNG 按完整采集批次顺序留出验证和测试，仍属同次实验，不能视为跨晶格独立验证。`test/legacy_20260116` 的 13 张原始 NPY 是额外旧相机图测试；加噪、衰减和旧识别结果未导入。`diagnostic` 是不同曝光/增益的 5 张原始图，不等于经过确认的标定暗场。

| 目录 | 用途 | 组织方式 |
| --- | --- | --- |
| `train/session_001/` | 无标注训练图 | 每次采集或每种稳定构型一个独立目录，可继续创建 session_002 等 |
| `val/session_101/` | 验证集，选择模型 | 使用另外的采集组；不能从训练组中随机抽相邻帧 |
| `test/session_201/` | 待识别图 | 可以是未见过的新晶格，递归读取所有支持的图像 |
| `reference/session_201/` | 可选全亮参考 | 必须与对应测试图同一构型、同一坐标及相机设置；单次 reference 命令只指向这一组 |
| `calibration/dark/` | 预留相机暗场 | 当前版本不会自动读取或扣除；不要误认为已完成相机标定 |

支持单帧二维灰度 `.png`、`.tif`、`.tiff`、`.npy`，推荐原始 16 位 PNG/TIFF。RGB、调色板图、多页 TIFF、三维数组、NaN/Inf 被拒绝。每个文件一帧；JPEG/BMP/SIF 暂不支持。原图数值转换为 float32，不会先压到 8 位。当前定位器接收非负原始 ADU；已经扣背景而包含负值的数据需另行处理。

**masked 路线：** 不需要同一场景的重复帧，也不需要坐标或状态标签；各种不同构型均可。仍须按采集组隔离训练与验证集。目录中只有一张图也可，但样本很少不能验证泛化。

**diffusion 路线：** 一个最末级目录就是一组重复帧。每组至少 3 张独立曝光，建议条件允许时采 8–16 张；位置、占据、亮暗状态、曝光、增益和光路必须保持稳定。输入帧不会混入自身的平均目标。不同晶格构型必须放在不同组。不要把全部随机图平铺到一个目录，也不要通过复制同一张图凑够帧数。本版没有自动配准。

例如可采许多不同构型，每个构型短连拍一组；整体划分 train/val/test。采集日期、离子数、曝光、EM 增益、冷却参数、RF 条件建议另存元数据表。目前目录分组生效，元数据表不会自动驱动训练。

每组名字应跨 train/val 唯一。程序检查相同目录、同名组及跨集合像素完全相同的图片；无法自动发现改名后的同一实验或高度相似帧。**训练验证划分的物理独立性仍需采集时保证。**

`.gitkeep` 只是保留空目录，可留着。真实图片、生成的 demo、模型和运行结果已被 `.gitignore` 排除，避免误推大文件。不要为了追踪图片而执行 `git add -f data`。

## 新增定位分支的数据准备（2026-11-04）

- **联合 PSF 拟合 `psf`：** 直接读取 `test/` 中的原始图像；光斑宽度、运动幅度等参数需要按实际成像条件设置，默认值不是本机标定结果。
- **直接点源网络 `points`：** 第一版通过在线模拟产生图像和中心标签，不需要把现有无标签大图伪装成已标注数据。模拟器参数及归一化会随模型保存；目前没有自动从相机数据拟合 PSF 的功能。训练的具体入口见 `ionrecog/point_localization/README.md`。
- **几何自监督 `equivariant`：** 为每张只含一个离子的原始灰度裁剪预留 `isolated_ions/train/session_001/` 和 `isolated_ions/val/session_101/`。这两处目前只有空目录，不含自动生成或已复核的训练样本。不要直接放整张多离子晶格，不需要标中心坐标。同一原图、同一构型的连拍和裁剪都应留在同一集合；验证集使用独立采集组。

本次只准备代码与空数据位置，未开始新方法的训练、推理或数据测试。使用入口与测试顺序见 [新定位方法指南](../docs/NEW_LOCALIZATION_METHODS.md)。
